# Prompt 15: job timeline and operations view (F15, F16) plus review fixes
## Goal
Make the dashboard service show the real product (operations and per-job timelines), separate from the scripted demo, and fix the issues found in review.
## Context
Prompts 01 to 09 done (10 and 11 if built). Read `docs/SPEC.md` section 3 F11, Appendix K (F15, F16, D17 to D19), `10-security.md`. Engine laws still apply. Run this after prompt 09 and before prompt 12.
## Scope
In scope: dashboard routes, timeline API, `stale_write_rejected` audit events, `/ops` and `/jobs/{id}` views, ledger read endpoint, one migration adding the read-only role `steadfast_dashboard_ro`, tests, screenshots.
Out of scope (do not touch): claim, heartbeat, complete, fail logic, fencing rules, schema other than the one role migration, the verifier, the readiness page (prompt 16). Anything else that needs a schema change: stop and ask.
## Requirements
Part A, review fixes and route split
1. Routes: `/demo` (existing demo UI, chaos buttons, Run Demo) served only when `STEADFAST_ENV=demo`, otherwise 404; `/` redirects to `/ops`; no chaos control anywhere else.
2. The stakes counters on `/demo` show "no verdict yet" (not 0) until a verdict exists for the current run, then show the numbers from the verifier and ledger.
3. Confirm the baseline panel counters move when the baseline lane runs. If they do not, find and fix the wiring and report what was wrong.
4. Add Kill Redis and Start Redis buttons to `/demo`, using the same chaos actions as `ctl chaos`.
Part B, timeline API and audit
5. `GET /v1/jobs/{id}/timeline` per Appendix K: tenant-scoped, 404 for foreign IDs, events built only from `audit_log` and `job_attempts`, error messages truncated to 500 characters.
6. When heartbeat, complete, or fail returns 409, write an audit row `stale_write_rejected` with endpoint, presented token, current token, worker. Stop writing after 20 such rows per job. No schema change.
7. Ledger: add `GET /ledger/entries?job_id=` (admin key, read-only) returning that job's applied and suppressed entries.
Part C, views
8. `/jobs/{id}`: vertical timeline, one band per attempt (worker, token, start to end, outcome chip), amber for `lease_expired`, red for rejected stale writes, state-change markers, and a "Downstream evidence" panel from the ledger labelled as independent of Steadfast.
9. `/ops`: login with `OPS_TOKEN` (generated by `seed` into `.env`), session cookie `HttpOnly` and `SameSite=Strict`, 8-hour expiry, constant-time compare, 5 login attempts per minute, Origin check on state-changing requests. Views: jobs by state per tenant, jobs table with filters (tenant, state, type, attempts greater than 1, job ID prefix) and pagination, DLQ inspect/edit/replay, audit log viewer, health strip. Quick filters "retried", "lease expired", "dead", "stale write rejected", and a presenter button "open a random retried job".
10. Migration for `steadfast_dashboard_ro`: SELECT on `jobs`, `job_attempts`, `audit_log`, and only `id` and `name` of `tenants`. The dashboard reads through this role; writes go through the Steadfast API with tenant keys held server-side.
## Security and privacy checklist
Tenant scoping on the timeline API; no `api_key_hash` readable by the dashboard role (test); all job data, payloads, and error messages escaped when rendered; payload shown only in job detail and truncated at 2 KB; no keys or OPS_TOKEN in the served bundle or logs; cookie flags set; Origin checks; audit cap prevents flooding; `/demo` unreachable outside demo mode.
## Method
1. Read spec and rules. 2. Produce a plan (route table, timeline event shape, role migration SQL, session design) and WAIT for approval. 3. Small commits. 4. Tests alongside code.
## Acceptance criteria
- A15.1 a reaped job's timeline shows attempt 1 `lease_expired` and attempt 2 `succeeded` with a higher fencing token (from a real chaos run).
- A15.2 the I4 zombie scenario produces a `stale_write_rejected` event on that job's timeline.
- A15.3 foreign tenant gets 404 on the timeline endpoint. A15.4 the 20-row cap holds (test).
- A15.5 the ledger panel shows exactly 1 applied entry for a retried job.
- A15.6 HTML in a payload or error message renders as text.
- A16.1 to A16.6 from Appendix K, each with evidence.
- `/demo` returns 404 when the dashboard runs with `STEADFAST_ENV` not set to demo; no chaos control is present in the `/ops` page source.
- Stakes counters show "no verdict yet" before a verdict; baseline counters move in a both-lane run.
- `ctl demo-short --headless` still passes with verifier exit 0.
## Verification
`go run ./cmd/ctl test`; `go run ./cmd/ctl lint`; `go run ./cmd/ctl scan`; `go run ./cmd/ctl demo-short --headless`; screenshots saved to `docs/evidence/`: ops summary, a retried job timeline, the zombie timeline, the "no verdict yet" counters; page-source grep proving no chaos control or token in `/ops`.
